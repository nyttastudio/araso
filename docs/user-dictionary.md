# 사용자 사전 재설계

학습한 단어(`lexicon.json`)와 키 대치(`replacements.json`)를 하나의 사용자 사전으로 합친다.
한자 후보 순서(`apple-learning.json`, AzooKey 학습)는 변환기의 기억이라 그대로 둔다.

## 지금의 문제

- 같은 쪽으로 두 번 고쳐야 기억한다. 한 번 고친 것(`once`)은 지워지지 않고 쌓인다.
  실제 파일에 `taxidnswjstndkwjTlkonnichiha` 같은 찌꺼기가 남아 있다.
- 키 전체가 같을 때만 적용된다. `촉매`를 기억해도 `촉매를`·`촉매가`에는 쓰이지 않는다.
- 학습, 키 대치, 한자 순서가 파일 세 개에 흩어져 있고, 설정 창에서는 한 탭에 섞여 있다.
- 미리 등록하는 길은 입력해 보기 → 키 대치 추가뿐이다. 언어만 정해 두는 등록은 없다.

## 항목

`dictionary.json`은 항목의 목록이다. 항목 하나는 **키 → 결과**이다.

```json
[
  { "keys": "chrao", "as": "korean", "from": "learned", "strength": "weak", "last": "2026-10-17" },
  { "keys": "chrao", "as": "korean", "from": "learned", "strength": "sure", "last": "2026-10-17" },
  { "keys": "hoge",  "as": "japanese", "from": "user" },
  { "keys": "rt",    "text": "감사합니다", "from": "user", "apps": ["com.tinyspeck.slackmacgap"] }
]
```

- 결과는 언어(`as`)이거나 내 글(`text`) 중 하나다.
- `from`
  - `user`: 사전 탭에서 직접 등록한 항목. 지우기 전까지 남는다.
  - `learned`: 바꾸기 키로 고쳐서 생긴 항목. 언어 항목만 이렇게 생긴다.
- `strength`(`learned`만 해당)
  - `weak`: 한 번 고침. 판단을 덮어쓰지 않고 점수만 민다.
  - `sure`: 두 번 고침. 지금의 `learned`처럼 이긴다.
- `apps`: 지금 키 대치와 같다. 없으면 모든 앱, 앱 자신의 항목이 이긴다.
  언어 항목에도 쓸 수 있다.
- 같은 키와 같은 앱에는 항목이 하나만 있다. 새로 등록하거나 학습하면 그 항목이 바뀐다.

## 학습 규칙

- 고친 언어가 엔진이 고른 언어와 같으면(되돌림) 그 키의 `learned` 항목을 지운다.
  `user` 항목은 건드리지 않는다.
- 처음 고치면 `weak` 항목을 만든다.
  - 그 언어 점수에 보너스를 더한다(앞 단어 쪽으로 미는 `contextBias` 정도).
  - 그래서 애매한 단어만 뒤집히고, 확실한 단어는 그대로다.
- 같은 쪽으로 다시 고치면 `sure`가 된다. 다른 쪽으로 고치면 그 언어의 `weak`로 다시 시작한다.
- 오래된 `weak`는 30일 동안 다시 고치지 않으면 읽을 때 버린다. `sure`와 `user`는 남는다.
- 기억하지 않는 경우
  - 키 대치가 있는 키(지금과 같다)
  - 내 글 항목을 돌아 나간 경우
  - 너무 긴 토큰(예: 20키 넘게). 문장을 한 덩어리로 바꿔 본 흔적은 단어가 아니다.
- "마지막으로 학습한 단어 되돌리기" 메뉴는 `sure`가 된 항목을 지운다.

## 적용 범위

- 내 글 항목은 지금처럼 키 전체가 같을 때만 적용하고, 맨 앞 읽기로 보인다.
- 언어 항목(`user`, `sure`)은 키 전체가 같으면 confidence 1로 이긴다. 이건 지금과 같다.
- 언어 항목은 뒤에 조사가 붙어도 적용된다. 모델의 어휘에 넣는 대신 `DictionaryEngine.withParticle`이
  직접 나눈다. 점수를 다시 맞출 필요가 없고, 사전이 비어 있으면 동작이 전과 같다.
  - 한국어: `촉매를`, `촉매가` = 단어 + 조사. 조사는 단어 끝소리에 맞는 꼴이어야 한다(사람은, 사람는 아님).
  - 영어: `ghostty에`(mixed), 일본어가 켜져 있으면 `ghosttyで`. 영어 단어 + 한국어 단어(`hello월드`)는
    넓히지 않는다.
  - 일본어: `hogeで`, `hogeから`.
  - 막는 것(`ParticleSplitter`와 같은 기준): 토큰 전체가 영어 단어일 때, 한 키짜리 단어, 대문자 없는
    3글자 미만 영어 단어(`to`+는은 새는), 토큰 전체가 한국어 단어(+조사)로 읽힐 때(`sha`+들을은 놈들을),
    영어 단어 + 일본어 조사인데 토큰 전체가 깨끗한 로마자일 때(`toki`+は는 ときは).
  - 점검: eval.tsv 6천 단어 전부를 항목으로 넣어도, en_50k 상위 2만 단어를 영어 항목으로 넣어도
    eval.tsv의 어떤 행도 나뉘지 않는다(막기 전에는 en_50k 쪽에서 28행).
- `weak` 항목은 어휘에 넣지 않는다. 분리는 확실한 것만 한다.
- 문맥(앞 단어 언어)별로 따로 기억하지는 않는다.

## 체인

`DictionaryEngine`(지금의 `LearningEngine` 자리) → `SplittingEngine` → `HeuristicEngine`.

- `sure`/`user` 언어 항목: 그대로 돌려준다. 렌더는 base가 한다(지금과 같은 이유).
- `weak`: base에 보너스를 넘긴다. `DecisionContext`에 `nudge: Language?` 같은 것을 둔다.
- 어휘: 사전이 바뀔 때 `KoreanModel`·영어·일본어 쪽 사용자 어휘 집합을 바꿔 끼운다.
  런타임에 바뀌므로 정적 집합과 따로 둔다.
- 내 글 항목은 지금처럼 `InputSession`이 엔진보다 먼저 본다.

## 설정 창

- 탭 이름: "학습한 단어" → "사전".
- 목록은 하나다. 열: 키 · 결과(언어 또는 글) · 출처 · 앱.
  - 결과 칸은 종류가 먼저, 나오는 글이 뒤다: `한국어 촉매`, `일본어 ほげ`, `내 글 감사합니다`.
  - 필터: 모두 / 등록함 / 학습함(확정) / 한 번 고침.
- **+** 버튼 → 시트
  - 키를 받는 칸. 일반 텍스트 칸은 IME를 거쳐 키가 아니라 글이 들어오므로,
    입력해 보기처럼 키를 직접 받는다(`TypingTrace`).
  - 그 키의 읽기들(영어·한국어·일본어·나눔)이 보이고, 하나를 고르거나 "내 글"에 입력한다.
  - 앱 제한(선택).
- 학습한 항목은 "등록으로 고정"할 수 있다. `learned` → `user`로 바꾸면 만료되지 않는다.
- 입력해 보기의 "키 대치 추가…"는 "사전에 추가…"가 되고, 키가 채워진 같은 시트를 연다.
- 행을 두 번 누르면 같은 시트로 고친다.
- 행 오른쪽: 📌 고정(학습한 항목만), ✕ 지우기. 한 번 고친 항목의 앱 칸에는 남은 날을 보인다.
- 시트의 선택지는 영어·한국어·일본어·내 글뿐이다. 나눔(`github에`)은 넣지 않는다.
  언어 항목이 조사 분리에 저절로 쓰이므로 따로 고를 일이 없다.
- 시트의 읽기 옆에는 적용 범위를 짧게 적는다(`— 촉매를, 촉매가에도`). 내 글에는 적지 않는다.
- 아래쪽: "한자 후보 순서 초기화…"(이 탭으로 옮김), "학습한 것 모두 잊기…"(등록한 항목은 남김).
- 메뉴 막대: "기억한 단어" → "사전…", "마지막으로 학습한 단어 되돌리기"는 그대로.

## 옮기기

처음 읽을 때 `dictionary.json`이 없으면 옛 파일을 옮긴다.

- `lexicon.learned` → `learned`/`sure`
- `lexicon.once` → `learned`/`weak`, `last`는 옮긴 날. 20키 넘는 것은 버린다.
- `replacements.json` → `user` 내 글 항목(키 대치가 들어온 뒤)
- 옛 파일은 `lexicon.json.migrated`로 이름만 바꿔 둔다(지우지 않는다). 읽을 수 없으면 `setAside`.
